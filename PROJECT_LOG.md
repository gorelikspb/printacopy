# Дневник проекта: PrintACopy

## 📋 Обзор проекта

**Цель**: Создать маркетплейс для печати документов — сервис, где люди, которым нужно что-то распечатать, находят ближайший принтер у владельцев в своём районе.

**Технологии**: 
- HTML5
- CSS3 (vanilla, без фреймворков)
- JavaScript (vanilla, без библиотек)
- LocalStorage для временного хранения данных форм

**Деплой**: Статический сайт, можно деплоить на любой хостинг (GitHub Pages, Netlify, Vercel и т.д.)

---

## 🗓️ История разработки

### Этап 1: Создание статического лендинга

**Что было**: Нужно было создать простой статический сайт-лендинг, который продаёт идею сервиса обеим сторонам (пользователям и владельцам принтеров).

**Решение**: Создан одностраничный лендинг с 4 основными блоками:
1. Хедер с призывом к действию и двумя кнопками
2. Блок для пользователей (форма: город + email + загрузка файла)
3. Блок для владельцев принтеров (форма: имя + email + город + чекбокс цветного принтера)
4. Блок "Как это работает" с простой схемой процесса

**Почему такое решение**:
- Статический сайт без зависимостей — быстрая загрузка и простота деплоя
- Vanilla JavaScript и CSS — нет необходимости в сборке, можно открыть файл напрямую
- LocalStorage для хранения данных форм — позволяет протестировать функционал без бэкенда
- Адаптивный дизайн — работает на всех устройствах
- Современный UI с градиентами и анимациями — привлекательный внешний вид

**Плюсы**:
- ✅ Быстрая разработка и деплой
- ✅ Нет зависимостей, нет build процесса
- ✅ Можно открыть файл напрямую в браузере для тестирования
- ✅ Легко кастомизировать и изменять
- ✅ Хорошая производительность (маленький размер файлов)

**Минусы**:
- ❌ Данные форм хранятся только локально (в LocalStorage браузера)
- ❌ Нет реальной отправки данных на сервер
- ❌ Нет валидации на стороне сервера
- ❌ Нет защиты от спама

**Подводные камни**: 
- Учли, что это MVP для демонстрации идеи, а не полноценный продукт
- Формы работают "фейково" — показывают alert и сохраняют в LocalStorage
- В будущем нужно будет добавить бэкенд для реальной обработки данных
- Сделали адаптивный дизайн с самого начала, чтобы не переделывать позже

**Что сделано**:
- ✅ Создан одностраничный лендинг (index.html)
- ✅ Реализованы все 4 блока согласно требованиям
- ✅ Добавлены две рабочие формы (для пользователей и владельцев принтеров)
- ✅ Реализован адаптивный дизайн для мобильных устройств
- ✅ Добавлена плавная прокрутка к секциям
- ✅ Формы сохраняют данные в LocalStorage (демо-режим)
- ✅ Современный UI с градиентами и анимациями

### Этап 2: Автоматизация создания скриншотов

**Что было**: Чтобы вести дневник проекта, нужны регулярные скриншоты страниц. Делать их вручную долго и не гарантирует единый стиль.

**Решение**: Добавлен простой Node-скрипт на Puppeteer (`scripts/capture-screenshots.js`), который:
1. Открывает локальный `index.html`
2. Делает скриншоты каждого из нужных блоков
3. Сохраняет их в `screenshots/01-*.png ... 05-*`
4. Снимает отдельный полный скриншот мобильной версии

**Почему такое решение**:
- Puppeteer легко запускается командой `npm run capture:screens`
- Работает с локальным файлом — не нужен сервер
- Быстро повторно обновить скриншоты после изменений
- Сразу выдаёт все нужные варианты (desktop + mobile)

**Плюсы**:
- ✅ Экономит время, минимизирует ручные действия
- ✅ Скриншоты всегда в едином разрешении и стиле
- ✅ Можно запускать сколько угодно раз
- ✅ Не требует дополнительных внешних сервисов

**Минусы**:
- ❌ Нужна установленная Node.js
- ❌ Puppeteer весит ~100 МБ (Chromium)
- ❌ Возможны отличия при обновлениях браузера

**Подводные камни**:
- Для Windows важно запускать из корня проекта (используется `file://`)
- При первом запуске Puppeteer скачивает Chromium — нужно интернет-соединение
- Если меняются селекторы секций, нужно обновлять скрипт

**Что сделано**:
- ✅ Инициализирован `npm` и добавлен `puppeteer`
- ✅ Создан скрипт `scripts/capture-screenshots.js`
- ✅ Добавлена команда `npm run capture:screens`
- ✅ Скрипт сохраняет 5 скриншотов в соответствии с требованиями дневника

## 🎯 Ключевые решения и их обоснование

### 1. Выбор vanilla JavaScript и CSS вместо фреймворков

**Решение**: Использованы чистые HTML, CSS и JavaScript без фреймворков (React, Vue) и библиотек (jQuery, Bootstrap).

**Обоснование**:
- ✅ Проект простой — одна страница с формами
- ✅ Нет необходимости в сложной реактивности
- ✅ Быстрая загрузка (нет дополнительных библиотек)
- ✅ Простота деплоя (просто загрузить файлы)
- ✅ Легко понять и изменить код

**Альтернатива**: React/Vue + CSS фреймворк (Bootstrap/Tailwind)
- ❌ Избыточно для простого лендинга
- ❌ Требует build процесс
- ❌ Увеличивает размер и сложность

## 📸 Скриншоты (места для добавления)

> **Примечание**: Скриншоты хранятся в папке `screenshots/` в корне проекта и **не публикуются на сайте** (если применимо). Это внутренняя документация проекта.

### Как автоматически обновлять скриншоты
1. Убедись, что установлены зависимости: `npm install`
2. Запусти команду `npm run capture:screens`
3. Скрипт сохранит файлы `01-hero-header.png` ... `05-mobile-view.png` в `screenshots/`
4. Используется локальный файл `index.html`, поэтому дополнительных серверов не нужно
