# Автоматизация скриншотов для дневника проекта

## Зачем
Во всех новых проектах, где ведётся `PROJECT_LOG.md`, нужно сразу закладывать простой механизм получения актуальных скриншотов. Это ускоряет обновление дневника и обеспечивает единый вид материалов.

## Базовый подход (рекомендуется по умолчанию)
Используем Node.js + Puppeteer:
1. Инициализируем `npm` в корне проекта (`npm init -y`).
2. Ставим `puppeteer`.
3. Создаём скрипт `scripts/capture-screenshots.js`, который:
   - открывает локальную версию сайта (обычно `index.html` через `file://`);
   - проходит по списку секций и делает скриншоты;
   - сохраняет файлы в `screenshots/` с понятными именами (`01-...`, `02-...` и т.д.);
   - (опционально) делает отдельный мобильный скриншот.
4. Добавляем npm-скрипт, например `capture:screens`, чтобы запускать командой `npm run capture:screens`.
5. В `PROJECT_LOG.md` описываем:
   - зачем нужен скрипт;
   - как его запускать;
   - какие файлы генерируются;
   - что нужно обновлять при изменении селекторов/структуры страницы.

## Когда можно отойти от шаблона
- Если проект не про веб-интерфейс или нет визуальной части — договориться с заказчиком и задокументировать альтернативу.
- Если есть CI/CD, можно интегрировать запуск скрипта в пайплайн (но минимальная локальная команда всё равно обязательна).

## Чеклист при создании нового проекта
- [ ] Создана папка `screenshots/`
- [ ] Настроен `npm` и установлен `puppeteer`
- [ ] Есть `scripts/capture-screenshots.js` (или аналогичный файл)
- [ ] В `package.json` добавлена команда для съёма скриншотов
- [ ] В `PROJECT_LOG.md` есть раздел «Как автоматически обновлять скриншоты»
- [ ] Описан список нужных скриншотов и их имена

**Важно:** Если требуется другой стек (например, Python + Playwright), подход допускается, но должен быть сопоставим по простоте запуска и описан в инструкциях проекта.
